# The Crepery ERP – Secure Trial Foundation

هذه حزمة تأسيس آمنة للتجربة المجانية: تسجيل دخول، إنشاء Owner لأول مرة، إنشاء حسابات مستخدمين، صلاحيات دقيقة (عرض/إضافة/تعديل/حذف/اعتماد/طباعة/تصدير) حسب القسم، ونطاق فرع، وسجل نشاط.

## تنبيه مهم جدًا
هذه الحزمة **ليست بعد نسخة ERP التشغيلية الكاملة** ولا تتضمن ربطًا آمنًا لوحدات الجرد والمبيعات والمخزون والرسبي والمرتبات وP&L الموجودة في الواجهة القديمة. لا ترفع بيانات حقيقية ولا تعتبر صلاحيات هذه اللوحة حامية لبيانات النظام القديم. يلزم نقل كل وحدة إلى API مستقل يطبق `require(module, action)` مع فلترة الفرع قبل التشغيل الحقيقي.

## إعداد Render
1. ارفع محتويات هذا المجلد إلى مستودع GitHub خاص جديد (ملفات المجلد في جذر المستودع).
2. Render: New → Blueprint ثم اختر المستودع الذي يحتوي `render.yaml`.
3. أنشئ قيمة سرية قوية لـ `OWNER_SETUP_KEY` في إعدادات الخدمة. لا تشاركها.
4. راجع إنشاء قاعدة PostgreSQL المجانية. الخطة المجانية مؤقتة وقد تنتهي/تُحذف بياناتها؛ استخدم بيانات وهمية فقط.
5. بعد النشر افتح رابط الخدمة. أول زيارة تعرض إعداد Owner. أدخل `OWNER_SETUP_KEY` الذي أعددته، ثم اسم المستخدم وكلمة مرور قوية (12 حرفًا على الأقل).
6. سجل الدخول وأنشئ مستخدمين تجريبيين.

## إعداد محلي
Python 3.11+:
```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
set OWNER_SETUP_KEY=choose-a-long-random-secret
python app.py
```
افتح http://127.0.0.1:5000

## ملاحظات أمنية
- لا توجد كلمة مرور Owner ثابتة داخل الكود.
- `SECRET_KEY` يُولد تلقائيًا محليًا، لكن على Render اتركه كقيمة سرية مولدة من Render.
- استخدم HTTPS فقط؛ إعداد Cookie Secure مفعل افتراضيًا.
- غيّر كلمات المرور المؤقتة قبل الاستخدام.
- لا تشارك `OWNER_SETUP_KEY` أو `SECRET_KEY` أو رابط قاعدة البيانات.
- لا ترفع ملفات Excel أو نسخ قواعد البيانات أو بيانات موظفين حقيقية إلى GitHub.
